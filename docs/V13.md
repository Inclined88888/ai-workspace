# ROOKS v13: one conversation, honest model integrations

Branch `development/rooks-v13`, from `development/rooks-v12` (`11eed35`). `main` is unchanged. Requirement statuses are
items 151 to 166 of `docs/ROADMAP.md`; integrations and their evidence are in `docs/INTEGRATIONS.md`.

## What changed for you

- **Ask, and the answer comes back to the same conversation.** Research, missions and coding tasks started in a
  conversation post their results into it when they are ready: the research report, the mission plan waiting for your
  approval, the mission's result, the coding agent's answer. Each shows as a card that keeps itself current, with
  Approve (for a plan) and Stop. Detailed pages stay one click away.
- **Spreadsheets get real figures.** Attach a CSV, TSV or Excel file and ask; ROOKS computes rows, column types, sums,
  means, medians and group totals in code, with a chart and a table.
- **Documents** it writes can be previewed (rendered) and downloaded from the chat.
- **Coding agents.** With the ROOKS Companion, the assistant can hand a task to the official Codex CLI or Claude Code
  in a folder you allowed, after you approve that task.
- **Check-ins** can be asked for in a conversation (by voice too). They always wait for your approval and keep quiet
  hours.
- **Navigation** is seven areas: Assistant, Home, Needs you, Projects, Library (notes, documents, files, research),
  Planner (tasks, calendar, automations), Work (missions, computer, agent team). The rest is under More. Every old
  address still works.
- **One connection directory** (Settings, AI models, All model connections) and **one model picker** (Automatic, then
  ready models, then models never tested, then models the AI mode does not allow).

## Architecture

```
 conversation ──► assistant (tools) ──► start_research / start_mission / run_coding_agent / create_checkin
      ▲                                   │ approvals: the existing gates (GATED_TOOLS, ALWAYS_ASK, permissions)
      │                                   ▼
      │                       existing engines: research.py, missions.py + workers, companion (agents.py)
      │                                   │
      └── coordinator.py ◄── jobs table ◄─┘  posts one message per stage (plan, final), never during a turn
```

- `coordinator.py`: a `jobs` row records which conversation started which work. A loop (every 3 s, or when a turn
  ends) posts a message when the work reaches a stage you need to see. It never starts, approves or spends anything.
  A posted result counts as outside content for that conversation, so later persistent actions there need approval.
- Job cards call the same endpoints as the Missions and Research pages (`/missions/{id}/start`, `/cancel`,
  `/research/{id}/cancel`), so budgets, reservations and checks apply unchanged.
- `tables.py`: CSV with Python's csv module; xlsx read with regular expressions over the cell parts, never an XML
  parser or spreadsheet engine; formulas not evaluated; size limits on every part.
- `coding.py` (server) and `companion/rooks_companion/agents.py` (your computer): see `docs/INTEGRATIONS.md`.
- `connections.py`, `verify.py`, `anyllm_engine.py`: the directory, capability tests, and the optional any-llm engine.

## Security and billing audit

Reviewed against the v13 diff, adversarially; each line is a property and how it is enforced or tested.

| Property | How | Evidence |
|---|---|---|
| Nothing consequential runs silently | Coding tasks and check-ins are in `ALWAYS_ASK`; missions still need plan approval; the coordinator only posts messages | test_v13_workflow; scenarios E, F, G, I |
| A coding task runs only after approval, from an attended channel | `coding.start` requires `ctx.approved`; tool hidden from schedules, agents, Telegram, missions | test_v13_workflow |
| Two independent opt-ins on your computer | Companion runs Codex only after `allow-codex on`, Claude Code only after `allow-claude-api on`; folder must be one you allowed; read-only mode refuses | test_agents |
| Agent sandboxes are not weakened | No `--dangerously-*`, no `bypassPermissions`; Codex `--sandbox workspace-write`; Codex refused if its sandbox fails a self-test | test_agents; INTEGRATIONS evidence |
| Claude Code has no shell | `--tools=Read,Edit,Write,Glob,Grep --disallowedTools=Bash`. Found in testing: `--allowedTools` alone left Bash available | scenario G (real CLI offered only Read and Edit) |
| No token or cookie is read, copied or relayed | The companion runs `codex login status` and keeps only the sign-in kind; nothing reads `~/.codex` or Claude credentials | test_agents (only version, status, sandbox commands are run) |
| A subscription is never turned into API billing by ROOKS | Claude Code only with `--bare` (API key only, per its help), and only with your opt-in; Codex is given no `OPENAI_API_KEY` or other key from the companion's environment, so it can use only the sign-in you set up for it | test_agents (environment checked) |
| Billing is stated before and after | The approval names the billing; the result states the agent's reported cost; ROOKS's spending limit is stated not to cover it | scenarios F, G |
| Capability tests cannot spend behind your back | Same guard as every model call; Free and Local modes refuse disallowed models; a test that may be charged needs confirmation | test_v13_connections |
| Stored coding output is redacted | Progress, results and errors pass through `sensitive.redact` | code review |
| Posted results cannot instruct the assistant unchecked | `has_external_content` counts coordinator posts, so gated tools need approval afterwards | test_v13_workflow (research) |
| Uploaded spreadsheets cannot run anything | No XML parser, no formula evaluation, part size limit, row and column caps | test_v13_workflow |
| AirLLM bridge exposure | Binds 127.0.0.1 by default; no auth, documented | addons/airllm/README.md |

Residual risks, stated plainly:
- The companion trusts the server's `approved` flag, as it does for all Computer Use actions. A compromised ROOKS
  server could start a task in an allowed folder with an agent you turned on. The agent's own sandbox and your folder
  choice still bound it.
- Codex's sandbox allows writes to temporary folders by design.
- Claude Code's permission rules decide what `Edit` may touch outside the folder; ROOKS relies on them.
- Embedding capability tests are not recorded in ROOKS's usage (the endpoint reports no usage).

## Performance and resources

Measured on this machine, server on localhost, `perf.py` and `resources.py`, v12 (`11eed35`) against v13, each run three
times; medians shown.

| Measure | v12 | v13 |
|---|---|---|
| Script downloaded, all pages | 700 kB | 713 kB (+1.9%) |
| Script for the first screen | 392 kB | 394 kB |
| Home content visible | 290 ms | 224 ms |
| Home content visible, CPU slowed 4x | 738 ms | 673 ms |
| Opening a 120 message conversation | 219 ms | 188 ms |
| Opening Tasks with 1,000 tasks | 214 ms | 249 ms (slower in all three runs; cause not isolated) |
| Opening a conversation with charts | 188 ms | 183 ms |
| Moving to Settings | 167 ms | 182 ms (the connection directory loads with it) |
| Moving to the Assistant | 67 ms | 68 ms |
| Background requests in a minute on an idle Home page | 8 | 8 |
| Server memory once started / after a minute idle | 108 / 115 MB | 108 / 114 MB |
| Server CPU in a minute idle (all background loops) | 0.14 s | 0.15 s |
| `GET /api/connection-directory`, `GET /api/conversations/{id}/jobs` | n/a | 3.6 ms, 1.9 ms |

The run-to-run spread is wide (Home content visible ranged 215 to 306 ms across the six runs), so differences under
about 40 ms are not meaningful except where all three runs agree. The chat polls for results only while a job is open
in the conversation on screen, and only while the tab is visible.
