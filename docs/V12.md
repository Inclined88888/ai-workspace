# ROOKS v12: usability, reliability and finish

Branch `development/rooks-v12`, from `development/rooks-v11.1` (`cdb720d`). No new capability was added. The work was
an audit of every screen in a real browser, fixing what was confusing or broken, a documented design system
(`docs/DESIGN_SYSTEM.md`), measured performance, and browser tests committed to the repository
(`workbench/tests/browser/`). Requirement statuses are items 142 to 150 of `docs/ROADMAP.md`.

## Bugs found and fixed

Each has a check in `workbench/tests/browser/test_regressions.py` or `test_keyboard.py`.

| Problem | Effect before | Now |
|---|---|---|
| Sidebar overflow stretched the page | The window scrolled into blank space below the app, on desktop and phones | One scrolling area; `screens.py` checks every page |
| A reply still arriving was written into whichever conversation was open | Answers appeared in the wrong conversation | Replies stay with their conversation; a failure elsewhere is announced |
| A new chat finishing later navigated back to itself | You were pulled away from what you were reading | Never navigates you away |
| One message box shared by all conversations | Text typed in one could be sent in another; leaving the page lost it | A draft per conversation, kept for the session |
| Note autosave cancelled on switching | An edit made just before switching notes or pages was lost | Saved on leaving; closing the tab with unsaved text asks first |
| Failed note save cleared the status | It looked saved | "Not saved" with Retry |
| Save response for a note you had left reopened it | The editor showed the old note under the new note's address | Only the open note accepts a response |
| Missions listed after seven workflow templates | Your missions were off screen | Listed first; templates fold away |
| Stop and Take control shown with Computer Use off | Controls that could do nothing | Shown only while ROOKS could act; a labelled on/off switch |
| Project budget in cents | "Spent this month: 0.0¢" | Dollars |
| Automations used UTC by default, set only in a hidden tab | A daily 8:00 briefing arrived in the evening in Sydney | New workspaces take the browser's timezone; Settings has a timezone control; Automations offers a one-click fix |
| Nine lists opened on mouse click only (Files only with Enter) | Notes, conversations, research, mail, skills, the inbox and more could not be opened by keyboard | Rows are real links or buttons |
| Escape on the search palette | Keyboard focus was lost to the page | Focus returns to where it was |
| Search and the phone menu | Both could be open at once | Opening search closes the menu |
| Model list flags cached across modes | Pickers could show the wrong availability after switching AI mode | Computed per request |
| Dark mode contrast on the selected conversation | Failed AA | Fixed |

## Screens

- **Home:** the five summary boxes are one panel with dividers. Finished checklist steps fold into one line. Missions
  show as "open", not "in progress", when a plan is still waiting for you.
- **Assistant:** the channel label shows only for conversations from Telegram or the terminal. Edit on your own
  messages appears on hover or focus (always on touch screens). The model picker fits its label.
- **Settings:** the AI mode panel shows the current mode in one line with a Change mode button. The model card is
  "Model in use" (it repeated the section title). Timezone has its own setting with a Saved confirmation; Appearance
  says "Saved for every device". The "cannot bill you" confirmation appears only in Free Cloud AI mode.
- **Free Cloud AI:** every model picker lists allowed models first and shows the others disabled, with the reason as a
  tooltip. Nothing is hidden and nothing paid can be picked by accident.
- **Research:** one empty state instead of two empty boxes.
- **Computer, Projects, Automations, Missions:** as in the table above.

## Performance

Measured by `workbench/tests/browser/perf.py` on this machine, with the server on localhost (medians; the CPU slowed
4 times for the "slow" row). Localhost hides network time, so download savings show more on a real connection.

| Measure | Before | After |
|---|---|---|
| Script downloaded for the first screen | 684 kB | 392 kB (335 kB app, 56 kB icons; other pages load on demand and are fetched in the background once idle) |
| Home content visible | 228 ms | 233 ms |
| Home content visible, CPU slowed 4x | 789 ms | 748 ms |
| Moving between pages in the app | 45 to 127 ms | 50 to 183 ms (Settings slowest: it now builds the full timezone list) |
| Opening a 120 message conversation (full page load) | 167 ms | 217 ms |
| Opening Tasks with 1,000 tasks (full page load) | 207 ms | 252 ms |
| Opening a conversation with charts | 205 ms | 221 ms |
| Background requests in a minute on an idle Home page | 33 | 8 |

Full page loads of a deep link are 20 to 50 ms slower because the page's code is now a second request; moves inside
the app are not, once the background fetch has run. The idle saving comes from the computer status, now checked every
2 seconds only while Computer Use is on (it carries the Stop control), every 15 seconds while it is off, and not at
all in a hidden tab. No dependency was added.

## Accessibility

- axe-core 4.10.2 on 22 routes at desktop and phone width in light and dark (88 runs): no serious or critical WCAG 2.2
  A or AA violation. Before v12 there was one (dark contrast).
- `test_keyboard.py` walks the app with the keyboard only (20 checks): skip link, focus ring, sidebar, adding a task,
  the search palette, opening notes and conversations, the composer, the phone menu.
- Not done: a test with a real screen reader, and a manual audit by a person. Automated checks cannot prove WCAG
  conformance.
