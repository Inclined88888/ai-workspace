# ROOKS v10: proactive check-ins, voice, calls, workers, research and Needs You

Branch `development/rooks-v10`, created from the verified v9.1 security baseline (`fcf520a`). Research behind the
design is in `docs/research/V10_RESEARCH.md`; requirement statuses are items 101 to 117 of `docs/ROADMAP.md`.

## Architecture

Nothing here adds a container, a service or a dependency. Everything runs in the existing backend process, uses the
existing SQLite database, and reuses existing parts:

| Feature | Module | Built on |
|---|---|---|
| Check-ins | `checkins.py`, `proactive_api.py` | The existing `scheduler.loop` (no second scheduler), the inbox, Telegram |
| Calls | `calls.py` | Check-in deliveries; a voice session for accepted invitations |
| Voice | `voice.py`, `components/Voice.tsx` | The ordinary assistant turn (`run_turn` with `voice=True`) |
| Workers | `workers.py`, `workers_api.py` | Missions (parent, approvals, write replay), the assistant turn with a tool allow-list |
| Research | `research.py` | The v9 research engine, extended in place |
| Needs You | `attention.py`, `pages/NeedsYou.tsx` | Reads approvals, workers, missions, research, topics, schedules, calls, tasks and projects live |

New tables: `topics`, `topic_runs`, `deliveries`, `call_invites`, `phone_calls`, `worker_tasks`, `worker_events`,
`evidence`; new columns on `research`. All are created by the normal start-up migration (`CREATE TABLE IF NOT EXISTS`
and `ADD COLUMN`); nothing existing is changed or removed.

## How each part stays safe

**Check-ins.**
- Facts are collected by code and compared per key with the last check.
- The model is called only when something is new, and it may decide that nothing is worth sending.
- Each delivery has a unique key (topic, slot, channel), so a slot is delivered once.
- A Telegram send interrupted by a restart is marked uncertain and never resent blindly.
- Retries keep the same slot, with backoff of 5, 15 and 60 minutes, followed by one failure notice.
- Quiet hours, per check-in and daily limits, and a per check-in spending cap apply. Past the cap, the briefing is a written list.

**Voice.**
- By default it uses the browser's speech services, and ROOKS says first that the browser maker may process the audio.
- A provider must be OpenAI compatible.
- A cloud destination needs consent naming where the audio goes, and changing the model clears that consent.
- "Local only" refuses cloud speech, and so does every local-only project.
- Audio passes through and is never stored or logged.
- Voice turns are not mined for memories.
- Ending a session touches only what was said in it.

**Calls.**
- In-app invitations happen only inside contact hours and the daily limit.
- Snooze works at most twice. A missed or declined call becomes one written briefing.
- The phone line needs:
  - your password for every change;
  - a number verified by a code call you start yourself (with an explicit cost confirmation on Twilio);
  - per day, per week and monthly cost caps.
- Calls are not retried, are never recorded, and always open by saying the caller is an AI.
- The test provider records what it would send and dials nothing.

**Workers.**
- Each worker's tools are its role's tools, narrowed by scope (read, draft, write) and by any list you give. The assistant checks the list on every call, and no approval can widen it.
- Writes outside drafts wait for your approval. Coding in the runner workspace follows the workspace's own settings.
- Work runs as part of the parent mission, so writes are recorded and replayed instead of repeated.
- Claims take a lease whose epoch fences every write, and reserve the worker's cap from the mission's shared budget and the monthly limit in one transaction.
- A model call that would take a worker past its cap is not made, so overshoot is bounded by one call's cost.
- Spend is read from the usage ledger.
- Untrusted text from pages, files and other workers reaches a worker as data, with an instruction never to act on it.
- Computer work never starts automatically.

**Research.**
- Rounds are bounded by depth (at most 4), by sources (14) and by time (10 minutes).
- A deterministic gate decides when evidence is thin; the model cannot argue past it.
- Quotes are found in the page by code. A claim whose quote is not on the page is dropped.
- Links in the ledger are only to pages that were actually read.

**Needs You.**
- Every option is a single action on one item; there is no blanket grant.
- Deferring hides an item without deciding it.

## What was verified, and how

- **Backend tests** (`workbench/backend/tests`): `test_checkins`, `test_voice`, `test_workers`, `test_research`, `test_needs_you` and `test_scenarios_v10`.
  - These cover scenarios B, D, E, F, G and H.
  - Scenarios A and C are tests in `test_checkins`.
- **Browser suites** (Playwright against the built app; scratch harnesses, not committed):
  - voice (26 checks): Chromium's fake microphone and a fake speech provider;
  - workers (11);
  - research (9): with a finished run seeded into the database;
  - Needs You (11): with an approval and an invitation seeded;
  - plus the earlier suites.
- **Every model reply in these tests is scripted.** No real model, speech service, phone line or public website was used. No call was placed and no paid service was activated.

Not verified:
- browser speech recognition;
- any real speech provider;
- barge-in on real speakers;
- a real Twilio call;
- the full research pipeline against public web pages in a browser run (it is covered by backend tests against local fake sites);
- macOS.

## Upgrading

No new packages, containers or settings are required, and nothing is turned on by itself:

1. Update to this branch the usual way (`upgrade.sh` for a packaged update, or `git pull` for a clone). It keeps your data.
2. Rebuild and restart: `docker compose up -d --build` (or your usual command).
3. The new tables are created at start-up.
4. Optional:
   - **Check-ins:** add them under **Automations**.
   - **Voice:** use the **Voice** button in the Assistant, and pick a speech provider under **Settings, Voice**.
   - **Calls:** set contact hours, and the phone line if you want it, under **Settings, Calls from ROOKS**.
   - **Workers:** add them on a mission's page.

To roll back, check out the previous branch or tag and restart. The new tables are ignored by older versions.
