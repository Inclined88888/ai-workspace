# ROOKS v14: one place to work, with honest states

Branch `development/rooks-v14`, from `development/rooks-v13` (`8221c2a`). `main` is unchanged. Requirement statuses are
items 167 to 178 of `docs/ROADMAP.md`. Screenshots before and after are in `docs/screenshots/v14/`.

## What was wrong

- **Approvals could do more than was reviewed.** An approval replayed its tool with a fresh context: the requester's
  tool list was lost, and `approved` skipped the tool check entirely. A worker limited to reading could, through an
  approval, run any tool. A project's budget was not checked when the approval ran.
- **Isolated projects leaked to the assistant.** Searching notes, files, tasks, missions, research and past
  conversations, and asking for project status, ignored the project boundary. A conversation outside a project could
  read an isolated project's notes.
- **Too many places to look.** The assistant had its own conversation column and four tabs (Chat, Memory, Skills,
  Settings) beside a seven-area sidebar with a More menu: three layers of navigation before typing anything. The first
  screen was a dashboard.
- **States that claimed too much or too little.** Connections used ten status words ("Ready", "Installed",
  "Connected", "Not checked"...). The AirLLM bridge, which ignores tools and still answers, could pass the connection
  check and become the automatic model or a backup.
- **Email triage could not read an email.** The assistant could search mail but not open a message, so it could not
  reply from what a message actually said.

## What changed for you

- **The assistant is the first screen.** Type straight away; four starting points (Write, Research, Analyse, Plan)
  fill the message box rather than sending.
- **One sidebar:** New chat, Search (Ctrl K), Projects, Needs your review, your recent conversations, then a Workspace
  fold with the detailed pages, Settings and Sign out. It collapses to icons and remembers that; on a phone it is a
  drawer.
- **Results beside the conversation.** A document, file or research report opens in a preview panel next to the chat
  (over it on narrow screens); Escape closes it.
- **Progress reads like a sentence.** "Searching your notes" while it works, then "Searched your notes, saved a note", with Details
  for the raw steps.
- **Connections say what was proven:** Verified, Connected but not tested, Available but not set up, Experimental,
  Check failed, Off. AirLLM is Experimental everywhere and never chosen for you.
- **Email triage:** ROOKS can search, read a message and save a threaded reply draft. It cannot send; the draft card
  opens Mail's Drafts, where you review and send.
- A warmer palette, one set of motion timings, reduced motion respected throughout, a darker dark-mode accent so white
  text on buttons passes contrast.

|---|---|---|

| Assistant conversation column with its own search | Recent conversations in the sidebar (latest 40); all of them through Search (Ctrl K) | One list, not two |
| Assistant tabs Chat / Memory / Skills / Settings | Chat is the assistant; Memory and skills is a Workspace page with its own tabs (Memory, Skills, Assistant settings) | No tabs above a chat |

Nothing was deleted: every page, and every older address, still opens (`/assistant`, `/assistant/:id`, `/library`,
`/planner`, `/work`, `/assistant-memory` and the rest). Main navigation has no new sections; no new agent types and no
new dashboard were added.

## Execution systems: consolidated and still separate

**One path (already, and enforced in v14).** Chat, Telegram, schedules, check-ins, company agents, mission steps and
workers all run through the assistant's turn loop (`assistant.run_turn` / `ask`, `Ctx`, `_run_tool`). That means one
set of permissions, one approval path (`request_approval`, `decide_approval`), and now one recorded approval scope
(the requester's tools, project, mission, task and channel) and one project boundary (`scope.py`).

**Still separate engines,** each reporting into the conversation through v13's coordinator jobs and into Needs your
review:

| Engine | Module | Why it stays separate for now |
|---|---|---|
| Deep research | `research.py` | Its own search, read and review rounds with an evidence ledger |
| Computer Use | `computer.py`, the companion | Runs on your computer through the paired companion |
| Coding agents | `coding.py`, `companion/rooks_companion/agents.py` | The official Codex CLI and Claude Code, on your computer |
| Browser agent | add-on service (`browser_proxy.py`) | A separate container, off by default |
| Voice and calls | `voice.py`, `calls.py` | Real-time audio pipeline |
| Paperclip, Hermes | add-ons | External applications, linked from Workspace |

Merging these into the turn loop would be a rewrite without a migration path; v14 did not attempt it.

## Files and decisions

| File | What and why |
|---|---|
| `backend/app/scope.py` (new) | The project boundary for assistant tools: outside a project, items in no project or a non-isolated one; in a project, its items and loose ones; in an isolated project, only its own. A file attached in this conversation is always readable there |
| `backend/app/assistant.py` | Tools wrapped with the boundary; approvals record their scope and are replayed in it; `approved` no longer skips the tool check; budgets checked when an approval runs; `read_email`; reply drafts |
| `backend/app/connections.py`, `llm.py`, `api.py` | One state per connection; `llm.experimental()` recognises the AirLLM bridge; it is never recommended, automatic or a backup |
| `frontend/src/components/Sidebar.tsx` (new) | The sidebar; recent conversations refresh on `rooks:convs` |
| `frontend/src/rich/Preview.tsx` (new) | The preview panel and its context, so cards can open it |
| `frontend/src/App.tsx` | Shell, routes (`/` assistant, `/overview`), page tabs |
| `frontend/src/pages/Assistant.tsx` | No column, no tabs; welcome; plain progress sentences |
| `frontend/src/styles.css`, `appearance.ts` | Tokens, motion, layout; the v14 layer is at the end of the file |

Decisions: the Assistant is now in the main bundle (it is the first screen), which costs about 73 kB of JavaScript on
first load compared with v13's first screen; Recent shows 40 conversations rather than paginating, because Search finds
the rest; AirLLM recognition uses what the bridge says about itself, not a port number.

## Limitations

- **Mocks are not live integrations.** The AI is a stand-in; email ran against a stand-in mailbox, not an IMAP server;
  Codex ran against a stand-in of the Responses API with a fake key. Nothing here shows how a real provider answers.
- **Claude Code (scenario G) was not run in v14.** Its detection runs `claude --version` without `--bare`, which this
  session does not run. Its v13 evidence stands; v14 changed only the badge it expects.
- **Windows and macOS** computer use and coding agents were **not tested**; only Linux.
- **Performance:** the long conversation and Settings are measurably slower than in v13 on this machine, and first-load
  JavaScript grew by 73 kB. Not fixed in v14.
- AirLLM behind a proxy that rewrites the model list, under a name without "airllm", would not be recognised.
- Screen readers were checked with axe and keyboard tests, not with a screen reader.
