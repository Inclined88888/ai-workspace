# ROOKS v15: one engine, three interfaces

Branch `development/rooks-v15`, from `development/rooks-v14` (`b471da9`). `main` is unchanged. Requirement statuses are
items 179 to 194 of `docs/ROADMAP.md`. How it fits together: `docs/ARCHITECTURE.md`. The DeepSeek Harness study and
decision: `docs/DSH_EVALUATION.md`. The desktop app: `docs/DESKTOP.md`. The terminal command: `cli/README.md`.

## What was found (audit of the code at the v14 tip)

- **Approvals and project boundaries:** the v14 fixes hold. Approvals keep the requester's tools, project and budget,
  run once (atomic claim), and cannot be changed at decision time (the body is yes or no). Missions replay approved
  actions from their record. Verified by reading the code and by the existing tests.
- **Five engines, five status vocabularies:** research (running, done, error, cancelled), missions (planning, review,
  queued, running, waiting_approval, paused, done, partial, failed, cancelled), workers (queued, running,
  waiting_approval, in_review, needs_you, blocked, done, failed, cancelled), coding tasks and agent tasks. Each client
  translated them its own way.
- **The terminal reached only part of ROOKS:** the terminal token worked on the assistant routes, not on projects,
  research or work, so a terminal could not follow what it started.
- **No way to know a saved file is the saved file:** previews showed text; nothing compared it with what was written.
- **Browser state went stale:** a conversation started elsewhere appeared only after a reload or a 30-second poll.

## What changed

**Core (Phase 2).**
- `work.py`: one typed lifecycle (created, planning, awaiting approval, running, verifying, paused, completed,
  failed, cancelled), an explicit transition table, and the one mapping from each engine's statuses.
  - The engines keep their own state machines; nothing was renamed.
  - Database triggers write every status change to `work_events` in the same transaction.
  - A test that runs last checks every change the whole suite produced against the table. It found that workers go
    back to queued after running, which the first mapping called "new".
- `v1.py`: the versioned API every client uses.
  - Endpoints: meta, status, conversations, chat, work (list, get, cancel, retry), approvals, projects, capabilities,
    files and live events.
  - Version negotiation answers 426 with what to update.
  - `Idempotency-Key` on chat: a retried request is answered from the first one, not run again.
  - Deciding an approval twice returns the decision already made.
- An approval request is audited ("approval asked"), pairing with the existing approve or deny record.

**Web (Phase 3).**
- **Live updates:** one live connection per browser. A chat started in the terminal appears in an open browser by
  itself, and job cards and the review count update when something changes.
- **Less background traffic:** an idle page makes 5 requests a minute, down from 7 in v13.
- **Previews:** images, PDFs and spreadsheets open beside the conversation as an image, in the PDF viewer, or as a
  table.
- **Saved-file check:** every file preview says whether what is on disk is what ROOKS wrote.
- **Status words:** job cards show the server's words for each state, the same words in every client.
- **Microphone:** shown only when this browser can hold a voice conversation.

**Terminal (Phase 4).** `rooks`, an installable package (standard library only):
- **Commands:** chat, ask, run (follows started work to the end), status, projects, conversations, show, jobs,
  approvals, approve, deny, connect, disconnect, doctor.
- **Scripting:** `--json`, `--no-input`, documented exit codes.
- **Token handling:** the token is never taken on the command line.

**Desktop (Phase 5).** Electron around the same web app:
- **Server care:** starts and looks after a local ROOKS (Docker install or a command), restarts it after a crash,
  and stops only what it started.
- **Notifications:** desktop notifications that open the conversation or Needs your review.
- **Companion:** pairs the ROOKS Companion and allows folders, only when you choose.
- **Installers:** Linux AppImage and .deb built and smoke-tested.

## Security

- **Approvals:**
  - An approval cannot be widened, changed or run twice (v14, re-verified).
  - Deciding again over the v1 API returns the recorded decision instead of an error that might prompt a retry.
- **Terminal token:**
  - Reaches the assistant routes and v1, never Settings (tested).
  - Never taken as a command-line argument.
  - Stored in a 0600 file or the system keychain.
  - A token from `ROOKS_TOKEN` is never written to disk (tested).
- **Files:**
  - Shown inline only if PDF or image, never sniffed; images under a sandbox policy.
  - An HTML upload is refused for viewing (tested).
- **Desktop page isolation:** the ROOKS page has no Node.js and no bridge. Other sites open in your browser. Only
  notifications and the microphone are allowed, for the ROOKS server (tested).
- **Desktop setup and folders:**
  - The setup bridge refuses calls from anything but the app's own page.
  - A remote server must use https unless it is on this computer.
  - Folders are granted only through the system folder dialog.
- **Audit:** every status change of every engine is recorded by the database itself.

## Limitations and risks

- **Desktop:** Linux only, unsigned, no automatic updates (`docs/DESKTOP.md` says what Windows and macOS need).
- **Live events:** each open client makes the server read its database every 2 seconds; fine for one person's
  workspace, not designed for many users.
- **Lifecycle:** a shared view and an audited contract, not a single state machine. An engine that sets a status the
  table does not know is caught by the test run, not prevented at run time.
- **Performance:** the 120-message conversation and Settings were slower than v13 (v14 item 178); not addressed here.

## Install and use

```sh
# Server (new install or upgrade; keeps data and settings)
curl -fsSL https://raw.githubusercontent.com/Inclined88888/ai-workspace/development/rooks-v15/install.sh | AI_WORKSPACE_REF=development/rooks-v15 bash

# Terminal
pip install ~/ai-workspace/cli
rooks connect http://localhost:3100   # token: Memory and skills, Assistant settings, Terminal access
rooks ask "What should I work on today?"

# Desktop (Linux)
cd ~/ai-workspace/desktop && npm ci && npm run dist:linux
sudo apt install ./dist/rooks-desktop_1.0.0_amd64.deb   # or run dist/ROOKS-1.0.0.AppImage
```
