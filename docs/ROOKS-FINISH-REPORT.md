## 4. #7 and the Tauri contradiction (L0b)

(a) install.sh has no app launch line. It calls desktop/launcher/install_helper.py, whose install_native() downloads
the release .dmg from GitHub Releases and copies AI Workspace.app into /Applications.
(b) Tauri v2 is live product code: desktop/src-tauri (Cargo.toml, src/*.rs), desktop/package.json,
.github/workflows/desktop.yml, the sidecar spec. Electron: 2 files mention it, none product code (lockfile names).
(c) desktop/launcher/ai_workspace.py native_app() returns `open -a /Applications/AI Workspace.app` when
Contents/MacOS/ai-workspace-desktop exists (on this Mac: Mach-O arm64, 6.2M, bundle id com.inclined88888.aiworkspace,
next to the 110.3M workbench-server sidecar). Chrome --app is only the fallback.

The launcher is Tauri. Decided: keep Tauri, the spec changes (docs/decisions/0001-app-window-is-tauri.md). Chrome
--app stays the fallback. #7 is built in the shared UI (Terminal page over /api/terminal/ws), so the app window gets it
with no Tauri command or permission; checked in WebKit, the engine of the macOS app window, not in a rebuilt .app.
